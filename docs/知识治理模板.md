# 组织知识治理模板

供各组织复用。确保知识库不是一次性搬运，而是**持续有人维护和使用**。

## 一、目录树设计原则

- 按**稳定的文档类型/职能**建树（团队会改名，用途更持久），不按组织架构。
- 深度 3–4 层封顶；跨维度用**标签**（项目、业务线、密级）而非无限加深目录。
- `90 待整理` 与 `99 归档` 是**一等目录**：低置信/未归类落待整理，过期移归档。

## 二、文件命名规范

`YYYY-MM-DD_<类型>_<简述标题>_v<版本>`，例：`2026-03-01_policy_远程办公指引_v2.docx`
- ISO 日期前置（可排序）；显式版本号；标题保留中文、去非法字符；
- 不在文件名放 owner/作者（组织事实用元数据承载）；**保留原始文件名为元数据**。

## 三、owner / steward 双角色（RACI 简版）

| 角色 | 职责 | 数量建议 |
|---|---|---|
| **知识 Owner**（问责） | 对某目录分支内容的准确性/相关性负责；批准重大变更、归档、密级 | 每分支 1 人/1 角色 |
| **知识 Steward**（操作） | 日常审查、清 `90 待整理`、跑巡检、执行复审节奏、处理确认队列 | 每分支 ≥1，且备份 1 人 |

> 每个分支至少两人熟悉，避免单点。owner/steward 记入 `config/taxonomy.yaml`，
> 新文档默认继承所在分支的 owner。

## 四、更新节奏（按风险分层，非一刀切）

| 内容类型 | 复审节奏 | 触发式复审 |
|---|---|---|
| 制度 / 安全 / 合规 | 每季度 | 法规变更、流程调整时立即 |
| 项目 / 模板 | 每半年 | 项目结项、模板改版时 |
| 参考 / 经验 | 每年 | 引用系统下线时 |

- 每份文档带**「下次复审日期」元数据**，使过期检测确定化（而非纯启发式）。
- 起步：每分支指定一人做季度巡检；成熟后转为随手小更新。

## 五、归档与保留

- 按分支定**保留期**（合同/合规长期；会议记录/草稿短期），见 `taxonomy.yaml` 的
  `retention_years`。
- 归档是**移动到 `99 归档`，不是删除**；记录归档**原因 + 时间**，可审计可回滚
  （对齐 ISO 15489 生命周期）。

## 六、健康度指标（上看板，定期复盘）

| 指标 | 定义 | 预警信号 |
|---|---|---|
| **沉淀比例** | 已入飞书 / 盘点范围 | 长期偏低 = 迁移停滞 |
| **过期率** | 过复审日未复审占比 | 上升 = 治理失效 |
| **待整理占比** | 落 `90 待整理` 占比 | 上升 = 目录有缺口，需增类 |
| **孤儿率** | 无 owner / 长期无人访问 | 上升 = 责任缺位 |
| **重复率** | 去重簇数量/占比 | 上升 = 上游授权纪律弱 |
| **复审完成率** | 按期完成复审占比 | 下降 = 流程本身没跑起来 |

- 定期把「待整理 + 低置信」桶做嵌入聚类，发现目录缺失的新类别，反馈到目录治理。

## 七、权限矩阵（飞书）

| 角色 | 空间/节点权限 | 对外分享 |
|---|---|---|
| 知识 Owner | 空间管理员 / `full_access` | 可管理 |
| Steward | `edit` | 关闭对外 |
| 一般成员 | `view` | 关闭对外 |
| 敏感内容 | 仅指定协作者 `full_access`，`only_full_access` 禁复制/下载/打印 | `closed` |

默认全局：`external_access=false`、`link_share_entity=tenant_readable`、
`invite_external=false`、`share_entity=same_tenant`。
